***Mitraillette***
=======================
MITRAILLETTE is a software designed to do some basic validations on ARPEGE, ALADIN, AROME, and
versions used by ALADIN or HIRLAM partners. It is shared between METEO-FRANCE, ALADIN partners and
HIRLAM partners. It is currently not used by ECMWF.

The current design of MITRAILLETTE allows to use it on different machines with minimal adaptations
concentrated in a reduced number of environnement files: that allows a minimal amount of work when scripts must
be adapted to a new machine. The design has been adapted in order that introduction of new configurations to
validate will be easy for everybody.

***Structure of the repository***
=======================
- doc\_mitraillette\_v042018.pdf : old but complete documentation (the scripts it describes,
  `mitraillette.x` and the job chaining, have been replaced by `mitpack`)

- PRO\_FILE.\[version\] : list of the test cases for a version of the tests (`PRO_FILE.CY50T1`,
  `PRO_FILE.CY51`)

- bin : `mitpack` (creates, runs and checks test cases), `mitsave` (used by `mitpack --save`),
  `xpnam`, `xpand`, `pjob2xpnam` (namelist tools)

- lib : Perl modules used by `mitpack`; jobs are generated by `lib/mitraille/generate.pm`

- namelist/\[cycle\] : Fortran namelists of the test cases

- io\_serv\_tools : utilities to run the io server

- protojobs : one `.pjob` file per test case (see below), and one directory per station (see below)

- tests/check-generate : regression check of the generation of jobs

- mitraillette.v102025.txt : some comments

***Running the tests with mitpack***
=======================
Mitpack creates a test case (one job per entry of a PRO_FILE), submits all its jobs at once, and
reports their status.

Setup: install this repository in `~/mitraille`, and create `~/.mitraille_profile`, for example:

```bash
export MIT_INSTALL_DIR=${HOME}/mitraille
export STATION=belenos     # a directory of protojobs: belenos, taranis, ecmwf
```

Then, from the directory of a pack or of a cmake build:

1) `mitpack` creates a new test case and submits its jobs. The version of the tests (the PRO_FILE)
   is guessed from the cycle of the build (`.genesis` for a pack, `CMakeCache.txt` for a cmake
   build): `PRO_FILE.CY<cycle>` if it exists, otherwise the only PRO_FILE of the same major cycle
   (CY50T1 for a 50t2 pack). Use `--version CY50T1` to choose; options can also be stored in a
   `.mitpack.conf` file in the pack (eg `["--version", "CY50T1"]`).
2) `mitpack --status` shows the status of each job; `--reference /path/to/pack-or-test-case` (one or
   two times) compares with other runs: `DIFF@<step>` gives the first step where the spectral norms
   differ, `DIFF-STRUCT` means that the norms cannot be compared.
3) `mitpack --reuse` reruns the last test case, `--cancel` cancels its jobs, `--dryrun` creates a test
   case without submitting it.

Other useful options: `--filter TL031,WENO` (Perl regexes on job names) runs some jobs only;
`--maxtime 40` or `--maxjob 20` runs several jobs one after the other in the same Slurm job (on the
ECMWF cluster, the number of jobs running at the same time is limited); `--save` saves the files
created or modified by each `mpilaunch` in `$SAVE_DIR/$CNMEXPL.N`. See `perldoc bin/mitpack.pl`.

A test case is a directory `mitraille_NNNN`. It is created in the pack when the pack is on a file
system shared between nodes (NFS, Lustre, GPFS); otherwise (eg `/tmp` of a node), in `$MITPACK_DIR`
(default `$MIT_INSTALL_DIR/<version>`), with a link in the pack.

On a cluster, `sbatch` passes the environment to the jobs: when mitpack is started from within a
Slurm job, clear `SLURM_CPU_BIND*` first (mitpack does it itself for the jobs it submits).

***Stations***
=======================
A station is a directory `protojobs/<station>` with:

- `site.sh` : settings of the site, included in every job: output and temporary directories
  (`WORKDIR`, `TMP_BASE`), input data (`INPUTFILES_HOME`, `INPUTFILES_WORKDIR`), LFITOOLS, the MPI
  launcher (`MPIAUTO`), machine values of the namelists (`MBX_SIZE`, `NCOMBFLEN`...), environment
  (modules, OpenMP, MKL, DR_HOOK...). A cycle that needs other settings can have `site_<cycle>.sh`.
- `sbatch.full` : Slurm directives of jobs using whole nodes.
- `sbatch.partial` : Slurm directives of jobs using part of a node (optional; without it, these
  jobs use whole nodes).
- `machine.conf` : description of the compute nodes (`cores_per_node`; `cpus_per_core` when Slurm
  counts hyperthreads as CPUs, as on the ECMWF cluster).
- `profil_table.csv` : resources of each profile: nodes, MPI tasks per node and OpenMP threads for
  the model (`*_fc`) and the IO server (`*_io`); `partial` = 1 for profiles using part of a node,
  `ntask_fc` x `nopmp_fc` cores (eg `half`, used by the TL030 and TL031 test cases).

`belenos` and `taranis` link to the files of `meteofrance`.

The sbatch files may use these placeholders: `__jobname__`, `__job_walltime__`, `__nb_nodes__`,
`__ntask_fc__`, `__cpus_per_task__`.

***Test cases (pjobs)***
=======================
`protojobs/<name>.pjob` contains the commands of a test case; `<name>` is the entry of the PRO_FILE,
and the name of its namelist (`namelist/<cycle>/<name>.nam`). It starts with:

```bash
# MITRAILLE PROFILE = half
# MITRAILLE TIME    = 10
# MITRAILLE COMMENT = Conf 001HYD sl2tl adiab TL031L15c1; no DFI; SETTLS; XIDT
```

`PROFILE` (a line of `profil_table.csv`) and `TIME` (minutes) are required.

The job generated for a test case contains: the Slurm directives, the task and thread counts
(`NPROC`, `NPROC_IO`...), `site.sh`, the settings common to all stations, then the pjob. When the
pjob starts, the current directory is the temporary directory of the job, and these are defined:

- `CNMEXPL` (name of the test case), `NAM_PATH` (namelists of the cycle), `BINDIR` (binaries of the
  pack or build), `MYOWNBIN` (`$BINDIR/MASTERODB`), the `FILE_PATH*` input directories;
- `getnam [--io]` : copies `$NAM_PATH/$CNMEXPL.nam` and sets the parallel distribution
  (`NAMPAR0`, `NAMPAR1`; `NAMIO_SERV` with `--io`), giving `namprovi`;
  `setnampar [--io]` does the second part only, on `${CNMEXPL}.nam`;
- `mpilaunch <binary>` : runs the binary with mpiauto;
- `shownode` : prints the listings of the MPI tasks (`NODE*`);
- `$CP`, `$ECP`, `$XPNAM`, `$IOPOLL`, `lficp`, `lfimv`.

***Checking the generation of jobs***
=======================
`tests/check-generate [REVISION]` generates all the jobs of all stations and versions with the
working tree and with a git revision (default `HEAD`), and compares them; use it before committing a
change to `lib`, `protojobs` or a PRO_FILE.
